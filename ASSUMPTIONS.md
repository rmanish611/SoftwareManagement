# Assumptions taken during execution

Decisions made on the owner's behalf while building, under the no-questions ladder. Each one is
implemented fully and reviewed by him in a single batch at the end, not one interruption at a
time.

| ID | Phase | Question | Chose | Because (ladder step) | Reversible | To change later |
|---|---|---|---|---|---|---|
| ASM-1 | P02 | LocalDB refuses connections on its own named pipe. Which engine does development use? | The already-running SQL Express instance (`.\SQLEXPRESS`, SQL Server 2025) | Step 1, the approved blueprint: ADR-00 names a running SQL Express service as the permitted alternative | Yes | The connection string in user-secrets and `STATE.json.environment.dbInstance`. See ADR-R01. |
| ASM-2 | P02 | The Angular 22 CLI requires Node 22.22.3+, 24.15+ or 26+; this machine has 24.13.0. | A project-local Node 24.20.0 under `tools/node`, verified against the official SHA-256 checksum and gitignored | Step 5, the most conservative and reversible option: upgrading the machine's Node would change every other project on it | Yes | Delete `tools/node`; `tools/get-node.ps1` restores it, and `.nvmrc` pins the version. |
| ASM-3 | P02 | The solution file format: .NET 10 now writes `.slnx` by default. | Classic `.sln` | Step 3, match the existing convention: `STATE.json.paths.sln` and the CI workflow were frozen against `backend/SoftwareManagement.sln` | Yes | `dotnet new sln --format slnx` and update the two paths. |
| ASM-4 | P02 | CA1707 forbids underscores in member names, but the exit gate requires test names carrying the requirement id, such as `REQ_LEAD_004_Returns400_WhenCaptchaTokenIsReplayed`. | Scope CA1707 off for `backend/tests/**` in `.editorconfig`; production code keeps it at error | Step 1, the approved protocol mandates the naming; a scope decision beats suppressing the rule with `NoWarn` or a pragma, both of which are banned | Yes | Remove the `.editorconfig` section once the naming requirement changes. |
| ASM-5 | P02 | EF Core's generated migration files cannot satisfy the nullable and style analysers. | Scope those rules off for `**/Persistence/Migrations/*.cs` in `.editorconfig` | Step 4, the documented default: generated code is excluded from style analysis everywhere. A `Directory.Build.props` inside a project subfolder was tried first and silently does nothing, because MSBuild only searches upward from the project file | Yes | One `.editorconfig` section. |
| ASM-6 | P02 | Generated migrations would dominate the coverage measurement (1,610 of 1,994 lines). | Exclude `**/Persistence/Migrations/*.cs` from coverage instrumentation in `coverlet.runsettings` | Step 5, the standard practice: generated code is verified by the D4 database gate, which applies every migration to a real server, rather than by unit tests | Yes | Delete the `ExcludeByFile` entry. |
| ASM-7 | P02 | Angular budgets cannot express "every lazy chunk is at most 250 kB" without naming each chunk. | `angular.json` enforces the 500 kB initial ceiling; `scripts/check-bundles.mjs` enforces the per-lazy-chunk ceiling over the real build output, in the gate and in CI | Step 5, the most conservative option that still enforces the approved NFR-PERF-03 number exactly | Yes | Replace the script with named bundle budgets once chunk names are stable. |
| ASM-8 | P03 | Smart App Control blocks freshly built unsigned assemblies from loading in the test host. | Retry only that specific block in `scripts/run-tests.ps1`, at most four attempts, and report the retry count | Step 5, the most conservative option: the alternative is switching off a machine-wide protection that cannot be switched back on without resetting Windows | Yes | Delete the retry loop, or exclude the repository from Smart App Control on the machine. See ADR-R03. |
| ASM-9 | P03 | Two application instances starting together both tried to seed the roles, producing a duplicate-key failure. | A SQL Server application lock (`sp_getapplock`) around the whole seeding routine | Step 5, and NFR-DEP-05 already requires a database lock for start-up and scheduled work | Yes | `SeedLock` is one class; removing it restores the race. |
| ASM-10 | P05 | The P05 exit table says a Sales token gets 403 on `/api/v1/admin/products`, but the frozen authorization matrix grants Sales product read (AZ-12) and withholds only writes (AZ-13). Which one is binding? | The authorization matrix. Sales reads the catalogue and cannot author it; the refusal asserted in the gate is the write, not the read | Step 1, the approved blueprint: `06-authz.md` is the frozen authorization contract, and the phase-plan line is a summary of it that was written loosely | No, the matrix is frozen | Only by an owner-initiated revision to `06-authz.md`, which would then change the tests with it. See ADR-R04. |
