# 07 Decisions (ADRs)

| ID | Topic | How it works | Pros | Cons | Fit for THIS project | Licence/Cost | Ecosystem | Reversal cost | Verdict |
|---|---|---|---|---|---|---|---|---|---|
| ADR-00 | Database & Tooling | SQL Server LocalDB via EF Core + SqlClient | Uses standard local DB, runs seamlessly in VS/dotnet | Requires Windows (but target is Azure SQL anyway) | High. Complies with guardrails. | Free (Express/LocalDB) | Massive | Low (just connection string change) | **Accepted**: SQL Server LocalDB for dev, Azure SQL for prod. |
| ADR-01 | Payments & Tax | Compare PSP (Razorpay) vs MoR (Paddle, Lemon Squeezy) | Razorpay acts as PSP, Paddle/LS act as MoR handling global tax compliance | MoR offloads global VAT liability; Razorpay has lower fees for Indian merchants | Razorpay requires manual global tax compliance; MoR charges higher % fees | High. As an indie dev in India selling globally, handling global VAT is a massive burden. | Razorpay (2-3%), Paddle (5%+50c), LS (5%+50c) | Excellent | High (requires full checkout rewrite) | **Accepted**: **Paddle**. As a single Indian dev selling globally, Paddle acting as MoR eliminates global VAT/GST registration headaches, outweighing the higher fee vs Razorpay. |
| ADR-02 | Architecture Style | Monolithic Web API + SPA | Single ASP.NET Core API serving JSON to Angular SPA | Simple to deploy, easy to reason about, single codebase | Scaling frontend and backend independently is slightly harder | High. Single seller means low overall load, monolith is perfect. | Free | Massive | High | **Accepted**: Monolithic Web API. |
| ADR-03 | Data Access Strategy | EF Core DbContext as Unit of Work | Controllers inject DbContext, modify entities, call SaveChangesAsync | Built-in tracking, no extra UoW abstractions | Can bloat controllers if logic is complex | High. Keeps codebase lean. Repository pattern rejected as redundant over EF Core. | MIT | Massive | Medium | **Accepted**: EF Core direct usage, Repository pattern rejected. |
| ADR-04 | UI Component Library | Angular Material vs PrimeNG vs Tailwind UI | Use standard UI components for frontend | Material is robust; PrimeNG has rich data grids; Tailwind UI needs paid license | Material can look "Googley", PrimeNG bundle size is larger | High. Need clean, accessible components for public storefront. | Material (MIT), PrimeNG (MIT), Tailwind UI (Paid) | Massive | High | **Accepted**: **Angular Material**. Tailwind UI rejected due to paid license. PrimeNG rejected due to larger bundle footprint for public-facing storefront. |
| ADR-05 | State Management | RxJS + Services vs NgRx | Component state managed via local subjects and singleton services | Simple, less boilerplate than NgRx | Harder to debug complex cross-component state | High. The public storefront has minimal complex state. | Free | Massive | High | **Accepted**: RxJS + Services. NgRx rejected as over-engineering for a storefront. |
| ADR-06 | Background Jobs | IHostedService vs Hangfire | Use built-in .NET background tasks | Free, built-in, no extra tables | Lost jobs on process restart unless explicitly persisted | High. We need reliable webhooks and email retries. | Free | Massive | Medium | **Accepted**: **Hangfire**. Built-in IHostedService rejected because process restarts drop in-memory jobs. |
| ADR-07 | Test Runner | Karma/Jasmine vs Vitest | Run Angular tests | Karma requires real Chrome; Vitest is headless/fast | Karma is Angular's default (though deprecated); Vitest requires custom builder | High. | Free | Good | Low | **Accepted**: **Karma/ChromeHeadless**. Selected for out-of-the-box Angular CLI compatibility despite RAM footprint. |

*Disqualifiers for Rejected Options:*
- **Razorpay**: Rejected because it requires the seller (me) to manually register and remit VAT/GST globally, which is unfeasible for a solo dev.
- **Lemon Squeezy**: Rejected in favor of Paddle due to Paddle's longer track record and mature B2B handling, though both are valid MoRs.
- **Repository Pattern**: Rejected because EF Core `DbContext` already implements Unit of Work and `DbSet` implements Repository.
- **Tailwind UI**: Rejected because it requires a paid license (budget is zero).
- **NgRx**: Rejected because the Redux boilerplate is overkill for a shopping cart and product catalog.
- **IHostedService**: Rejected for critical tasks because queue is lost on IIS/AppService restart.
